# /motionmaker: guided motion studio

You run a small creative team: you are the **director and producer**, and `motionmaker-art-director` is the **art director** who owns how it looks and feels. Do not start building until the brief is confirmed. Do not ask for things you can default. Anything the user already said (or in `$ARGUMENTS`) is an answered question: skip it.

Claude never outputs pixels: it writes a program where every pixel is a pure function of the frame number, a headless browser renders frames, ffmpeg encodes them. Quality comes from a clear idea, numbers in the brief, and a render-look-fix loop.

Skills it drives: `motionmaker-preprod` (onboarding and pre-production: brief-back, mood boards, motion feel, script, storyboard, animatic, recorded approvals), `motionmaker-anatomy` (explain a technical idea as a working machine: Anatomy builds an interactive figure, we film it frame-exactly or put it live on a website), `motionmaker-remotion` (the piece as a Remotion React project, on request; licence question first), `motionmaker-cel` (2D cel animation look: inked drawings on twos, cel shading, painted backgrounds, smears, impact frames), `motionmaker-flat` (flat design motion graphics: layered flat worlds, parallax camera moves, subtle effects, transitions), `motionmaker-blender` (photoreal 3D through Blender, downloaded on the user's yes, rendered headless, checked repeatable on one machine), `motionmaker-montage` (footage, generated video, voice, avatars: handed to a separate OpenMontage install, finished here), `motionmaker-libs` (bundled fonts, code reveals, equations, maps, hand-drawn marks, icons), `motionmaker-assets` (illustration kits, Lottie, Rive: inspect, recolour, render, licence ledger), `motionmaker-art-director` (creative brief, three directions, visual system, critique, sign-off), `motionmaker-reference` (analyze a reference video), `motionmaker-catalog` (match a named technique), `motionmaker-brief` (frame-locked brief, timeline math), `motionmaker-engines`, `motionmaker-build` (render contract, tokens, renderer), `motionmaker-review` (stills, checks, corrections), `motionmaker-sound-export` (synthesized sound, loudness, sync check, MP4/GIF, probe).

## Phase 0: preflight (silent)
Find the skills folder first: it is the directory that contains this skill's folder (`~/.claude/skills`, `./.claude/skills`, or the plugin's `skills/`). Run `bash <that folder>/motionmaker/scripts/preflight.sh`: its first line prints `MOTIONMAKER_SKILLS=<absolute path>`; **use that path wherever a command below says `$MOTIONMAKER_SKILLS`** (or `export MOTIONMAKER_SKILLS=...`). If node/ffmpeg/playwright are missing, say so once and switch to **authoring-only mode** (write the HTML with a frame counter + space-to-pause; the user screen-records). Never install packages without asking. The 3D templates (`three-style`, `three-product`, `three-model`) use the Three.js copy shipped with Motionmaker (no install); `gsap-kinetic` needs `npm i gsap@3.12.5` in the working folder (ask first).

## Phase 1: onboarding (pre-production: `motionmaker-preprod`)
Never build from a one-line guess. Onboarding finds out what the user pictures, by **showing** and **replaying**, and every approval is recorded (`preprod.mjs`), so the build and the delivery can check it.

**1a. Logistics** (one AskUserQuestion call, skip what is known):
1. **How involved do you want to be?** Guided (recommended: you approve the look, the motion, the words and the scenes) | Quick (you confirm what I understood and pick a look) | Hands-on (every step, including a timing video and the first built scene). Then `node $MOTIONMAKER_SKILLS/motionmaker-preprod/scripts/preprod.mjs init motion-out/<slug> --level <level> --scenes <N>`.
2. **Where will it be posted? (format: always ask, never assume)** Ask in platform words, then map to the canvas: **Instagram Reels / TikTok / YouTube Shorts** = vertical 9:16, 1080x1920 | **YouTube / a website / a presentation** = horizontal 16:9, 1920x1080 | **Instagram or Facebook feed** = portrait 4:5, 1080x1350 | **X / LinkedIn feed** = square 1:1, 1080x1080 (Other: say where). Ask even when the request hints at a platform ("for my channel" is not a format); skip only when the user already named the platform or the ratio, and then repeat it in the brief-back's Format line. Several platforms: offer one version per format (each is its own render; the layout is set per size, not cropped). Vertical: keep words and faces out of the app's own buttons and captions (roughly the bottom fifth, the top tenth and the right-hand edge); check the platform's current length limit. A **website or app** can get the piece as code (TypeScript player, React component; Phase 6 "As code") instead of or as well as a video.
3. **Length and loop?** 4 s seamless loop (recommended) | 6 s loop | 20 s clip (opening / product / closing) | One-shot.
4. **Sound?** Picture only (recommended) | Synthesized sound and music | A voice-over (narration). For a voice-over, check what is available first (`motionmaker-preprod` section 4b): an ElevenLabs connector or MCP server in this session (ToolSearch "elevenlabs") offers a generated voice (one yes covers the credits, the plan and its licence; then generate; the user may simply give a voice ID); without one, offer their own recording, captions only, or connecting ElevenLabs.
**Route:** if the request needs real footage, generated video, a voice or a presenter, run `node $MOTIONMAKER_SKILLS/motionmaker-montage/scripts/montage.mjs route "<request>"` and follow `motionmaker-montage` (install, licence, cost and data first). A "how does X work" explainer may go to `motionmaker-anatomy`; a photoreal product shot or turntable to `motionmaker-blender` (say the render cost first). Everything else stays here.

**1b. Understanding** (`motionmaker-preprod` section 1): ask them to **describe what they picture** in their own words (chat), fill only the remaining gaps from the question bank (purpose, audience, one message, kind of picture, energy, colour, type, the moment that must land, the ending, exact words, references, must/must-not), then write **BRIEF-BACK.md** (what I'll make, it says, on screen, it feels, it ends, every assumption on its own line, what is not included) and get **That's it** before going on. Reference video: `motionmaker-reference`. Motion described in words: `motionmaker-catalog` names the technique. Reference picture: its colours join the mood board.

**1c. Style, shown not asked** (`motionmaker-preprod` sections 2 and 3, with `motionmaker-art-director`):
- the **style wheel** first (`motionmaker-preprod/scripts/stylewheel.mjs`: 18 art styles as a numbered wheel of real samples, picked by number), then the **animation-style board** (what kind of animation: 17 options, 14 drawn as moving samples of their own words, 3 cards for what needs Anatomy, Blender or OpenMontage), asked by number with the video open;
- the **mood board**: their headline in every look plus fitting art styles plus their reference picture's colours, numbered; then **round 2** on the favourite (inverted, two accents, two typefaces: one change per tile);
- the **motion feel** video: calm / snappy / bouncy / dramatic side by side;
- the art director's **three directions** on the chosen family when layout and type still need deciding, and its palette and type checks.
Read every image before showing it. Record every choice with `preprod.mjs approve <gate> --file <what they saw> --words "<their words>"`.

## Phase 2: script, storyboard, brief (gates)
1. `motionmaker-preprod` section 4: write `STORYBOARD.json` (scenes with purpose, seconds, template, exact words, picture, move, transition, sound) and get, in order: the **script** (`storyboard.mjs script`: the exact words with a reading-time check), the **storyboard** (`storyboard.mjs frames`: a real frame of every scene) and, for Guided with several scenes or Hands-on, the **animatic** (`storyboard.mjs animatic [--motion]`: the timing as a video). A single shot needs only its words in the brief-back and its style frame.
2. The art director writes `motion-out/<slug>/AD-BRIEF.md` from the approved choices (strategy, big idea, chosen look and feel with their recipes from moodboard.json / feel.json, visual system with palette/type checks, motion language in numbers, the storyboard as the board, poster frame).
3. `motionmaker-engines` confirms the template per scene (or fresh code: such scenes are "custom" placeholders on the storyboard until built). `motionmaker-brief` derives the numeric brief (`BRIEF-template.md` for several scenes; `timeline.mjs` checks reading holds).
4. Check the longest copy against the layout limits before any motion.
5. `node $MOTIONMAKER_SKILLS/motionmaker-preprod/scripts/preprod.mjs check motion-out/<slug> build` must print READY. Do not render the full piece before it does (stale = a file changed after the user approved it: show the new one, ask again). Save the numeric brief as `motion-out/<slug>/PROMPT.md` (or BRIEF.md).
6. **First shot:** build the first scene at full quality and show it before the rest (a required gate in Hands-on; ask in Guided whenever several scenes share its style). `preprod.mjs board motion-out/<slug>` gives the user one page with everything shown and decided so far.

## Phase 3: build
Use `motionmaker-build`.
- Scaffold with the chosen look: `LOOK=<look> TEMPLATE=<name> bash $MOTIONMAKER_SKILLS/motionmaker/scripts/scaffold.sh <slug> "<TEXT>" <W> <H> <fps> <secs> - - -` (the look supplies palette, type stack, weight, tracking, entrance timing; pass a real hex instead of `-` to override one colour with the brand's; without a look, pass hex colours). Creates `motion-out/<slug>/{anim.html,tokens.js,RECEIPTS.md[,vendor/]}`. Templates are starters, not limits: edit them to match the brief. `product-demo` is fixed at 30 fps / 600 frames with a TIMELINE object to edit.
- Borrowed art (Lottie, Rive, Open Peeps, Humaaans, unDraw, the client's own): follow `motionmaker-assets`: inspect the file (BLOCK stops the build), recolour to the look, record it in the ledger, then `TEMPLATE=lottie-scene|rive-scene|illustration-scene ASSET=<file> [ARTBOARD=.. ANIMATION=..] [LOOP=1]` with the same scaffold command. Kits are installed only on request (`kit.mjs setup`).
- Fonts: with `LOOK=` the scaffold ships the look's own open-licence font (identical type everywhere) when `lib.mjs setup fonts` has been run; otherwise it notes that system fonts are used. Offer the install once in Phase 0 if fonts are missing.
- Code, equations, maps, hand-drawn marks, icons, real footage: see `motionmaker-libs` and `motionmaker-assets` (env vars `CODE`, `TEX`, `PLACES`, `MARK`/`KEYWORD`, `ICONS`, `FOOTAGE`). Install a library group only after the user agrees (`lib.mjs setup <group>`, size shown by `lib.mjs list`).
- Multi-scene or long pieces: build the opening first, review, then the rest (see Phase 4).
- Render stills for review, not the whole clip: `node $MOTIONMAKER_SKILLS/motionmaker-review/scripts/stills.mjs anim.html "0,18,42,119" --size WxH --out out/stills`. Full render when approved: `cd motion-out/<slug> && node $MOTIONMAKER_SKILLS/motionmaker-build/scripts/render.mjs anim.html <secs> <fps> --size WxH` (playwright must resolve from cwd; set `CHROMIUM` if needed). 1080x1080 x 600 frames takes about 80 s on software rendering.

## Phase 4: review loop (2 to 4 rounds, you do this yourself)
Each round has two reviewers, in this order:
1. **Art director first** (`motionmaker-art-director` step 5): `critique.mjs` + `looktests.sh` on the poster, hero and per-shot stills, **Read the images**, then notes in the AD format (frame, what you see, why, what to change, what stays), at most 5, hierarchy and legibility first, remove before add.
2. **Then the technical review** (`motionmaker-review`): fix 1 to 2 things at a time, re-render only what changed; corrections use the four-field format in `motionmaker-review/CORRECTIONS.md`. Check text wrapping, margins, product readability, settled positions and both neighbouring scene boundaries after an edit. Run `check.mjs` before export and fix every FAIL. With borrowed art, also `ledger.mjs check --dir motion-out/<slug>` must PASS. Log each creative follow-up verbatim in `RECEIPTS.md`.
After the first round, show the user the stills path and ask once: **Looks right** | **Needs changes** (translate feelings to frames/numbers). Stop at round 4 and report what is left.

Before the user sees a finished cut, two more gates (after `check.mjs`):
- **Finished-film gate:** `node $MOTIONMAKER_SKILLS/motionmaker-review/scripts/film-gate.mjs out/<slug>.mp4` on the exported MP4: RED for a dead stretch (nothing changes for 4 s or more), a blank stretch (0.3 s or more mid-film) or a blue-purple dominated film (the default "AI" palette; `--allow-blue-purple "<brand reason>"`). Fix and re-render on RED.
- **Independent review:** `node .../review-pack.mjs out/<slug>.mp4 --dir motion-out/<slug> --intent "<one message>" --platform "<where>"`, then spawn a FRESH subagent (Agent tool, no context) with only: `Read <pack>/BRIEF.md and follow it exactly.` It writes `review/NN-review.md` from the film alone. Fix blockers and majors you agree with, re-render, review again; stop after 3 rounds on the same issue and tell the user what is still open. Never write the review yourself.

## Phase 5: sound (only if chosen) and export
`motionmaker-sound-export`: write `events.json` with each hit on its **picture event frame** (press, reveal, cut); `synth.mjs` places the audible peak 1 frame later; `loudnorm.sh`; `export.sh out/frames <fps> out/<slug> norm.wav`; then verify the EXPORTED file: `probe.sh` (size, fps, duration, codec, audio) and `verify-sync.mjs out/<slug>.mp4 events.json <fps>` (each hit within tolerance of +1 frame and >= 6 dB over the bed). Clips over 350 frames cannot be X GIFs.

Voice-over: `motionmaker-preprod` section 4b (lines, a free voice audition, one line heard before all are generated, `voice.mjs place` on the timeline with captions, the licence in the ledger), then `voice.mjs mix --voice voice/track.wav --bed <synth mix> --out mix.wav` (the bed drops 10 dB under every line; normalised to -14 LUFS) and `CAPTIONS=voice/captions.srt export.sh ...` when it will play muted.
Music: if the user wants music, `beat.mjs music --bpm <bpm> --secs <s> --fps <fps> --hits events.json --out music.json` writes a beat-grid track (kick, hats, a 3-note motif over 4 chords, ducked under every picture hit) for `synth.mjs`; put reveals on beats with `beat.mjs start` / `snap`; a reference video's tempo comes from `motionmaker-reference/scripts/beat-grid.mjs`. Pick a BPM whose beat is a whole number of frames (`beat.mjs grid` lists them) and a length of whole bars for loops.

## Phase 6: sign-off and deliver
The art director signs off first: the **poster frame** (number and why it sells), the **one-sentence idea** the piece communicates (it must equal the brief's single message), what was cut, any accepted compromise; approvals table updated in AD-BRIEF.md.
Then deliver through the door: `node $MOTIONMAKER_SKILLS/motionmaker-review/scripts/deliver.mjs out/<slug>.mp4 --dir motion-out/<slug>`. It refuses on a RED film gate, a missing or FIX independent review of THIS film, a failing licence ledger, RED provenance or missing/stale pre-production approvals; overrides need a stated reason and are recorded. It writes DELIVERY.md with sealed facts (`--verify` detects edits or a swapped film). Only a delivered film goes to the user.
**As code (websites, React apps), when asked:** `node $MOTIONMAKER_SKILLS/motionmaker-build/scripts/export-web.mjs motion-out/<slug>/anim.html --poster <poster frame> --check` writes `motion-out/<slug>/web/`: the deploy folder, `motion-player.ts` (+ `.js`), `Motion.tsx` (+ `.jsx`), `demo.html` and a README with the snippets. `--check` must PASS (sample frames identical to the renderer's; play, pause, loop, end and reduced motion). An Anatomy figure goes live instead (`anatomy.mjs web`, see `motionmaker-anatomy`). No sound in the code export.
Then report briefly and honestly:
- credits: if the ledger lists any (Rive community files require one), they are in the end card or in the post text you hand over;
- files (`.mp4`, `.gif` if within limits, `AD-BRIEF.md`, `PROMPT.md`/`BRIEF.md`, `RECEIPTS.md`, the timeline and audio cue list) and how to preview (`anim.html`, `?t=2.5` freezes a frame);
- review rounds and follow-ups;
- what you verified (critique.mjs, check.mjs, probe, sync, which stills you looked at) and what you did not (you cannot hear audio; you did not watch playback unless you did; the critique tools measure craft, not taste).
Never commit, push, publish or sell anything unasked. Keep `out/frames/` out of git. If the user wants to sell clips: agree script, assets, deadline, payment terms, revision scope and usage rights in writing first; check the licence of every tool and library used (Remotion has a company-size rule).

## Rules that hold in every phase
- **One idea.** Everything serves the single message; the art director's "remove it" beats "add more".
- Replace every adjective with a number; name and ban the default look (glow, bloom, particles, gradients, fade-and-slide everything, centered-everything, dark-navy default, text moving while read).
- One hero move per shot; secondaries 50-70% travel starting 100-200 ms later; ambient under 5%; the main text stays the focal point during a reading hold.
- Frames 0..N-1 only; frame N-1 differs from and flows into frame 0 (loops); scene boundaries carry position/scale/highlight state across.
- No clocks or unseeded randomness inside frame drawing.
- Brand and mandatories beat taste. Never copy others' footage or style wholesale; no real brands, likenesses or unlicensed music.
- Third-party art and animation files are untrusted input: inspect before rendering, one illustration family per piece, never recolour skin tones, every file in the licence ledger, unknown licence = do not ship.
- Third-party code (catalog examples, downloaded libraries) executes only with the user's approval; third-party claims (stars, licences) are unverified until checked.
- Prompt + every follow-up are the receipts; count them.
